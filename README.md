# VibeGuardBench

**Can vibe-coded apps survive their own fixes?**

An empirical study and benchmark measuring whether AI application builders can
repair deterministic, tool-detected failures in their own generated full-stack web
applications — **without breaking what already worked**.

**Status: preregistered research protocol + validated harness. The commercial-
builder experiment is in progress. No results are claimed anywhere in this
repository.** See [reviews/final-verification-report.md](reviews/final-verification-report.md)
for the exact executed-vs-not-executed audit.

## The research question

> When deterministic engineering feedback identifies failures in an AI-generated
> full-stack application, can the same AI builder repair those failures without
> introducing regressions in previously passing functionality?

Prior work evaluates initial generation (WebGen-Bench, FullStackBench, AppWorld),
patch repair of human repositories against unit tests (SWE-bench and successors),
and patch overfitting in classical APR (Smith'15, Poracle, Lou'24). The combination
studied here — commercial prompt-driven builders, exported full-stack apps, a
deterministic multi-category oracle suite, machine-generated repair feedback, and
whole-suite regression measurement across iterations — is, per our search, an
unmeasured coverage gap. We claim a gap, not a "first"; see
[docs/lit-review/novelty-assessment.md](docs/lit-review/novelty-assessment.md).

## Design (frozen v1.0.0, amended v1.0.1–v1.0.2 pre-data)

```
3 application tasks  ×  2 AI app builders  ×  3 repetitions   =  18 apps (iteration 0)
                                                            ↘ up to 3 repair iterations each
```

After every repair, **the entire suite re-executes** — the whole-suite rule.
Regressions are only visible to checks that run.

## Oracle categories (39 checks)

| Category | Checks | Tools |
|---|---|---|
| BUILD | 5 | npm install/ci, build, start on `$PORT`, reachability, startup hygiene |
| TYPE | 1 | `tsc --noEmit` |
| LINT | 2 | ESLint (frozen config incl. Node+browser globals) |
| FUNC | 10–11 | Playwright (Chromium) against the interface contract |
| AUTHZ | 6 | API role×route probes, cross-owner writes, UI denial, logout invalidation |
| SEC | 6 | frozen Semgrep ruleset, secret scan (seed-credential-exempt), `npm audit`, SPA-aware debug probes, cookie/token storage, credential storage |
| A11Y | 4 | axe-core (WCAG 2.1 A/AA subset) + lang/title |
| DB | 4 | restart-based persistence + contract schema shapes |

Scanner findings are **candidate findings**, never reported as confirmed
vulnerabilities; manual verification and a false-positive sensitivity analysis are
part of the frozen protocol.

## Running the harness (prerequisites)

Linux/macOS with Node ≥ 20 (tested on 24), Python ≥ 3.10, `semgrep` on PATH
(`pip install semgrep`), Playwright Chromium (`npx playwright install chromium`).

```bash
# 1. install oracle toolchain
cd oracles && npm install && npx playwright install chromium && cd ..

# 2. point the suite at any exported application directory
python3 runner/run_oracles.py --run-id APP-01-DEMO-r1-i000 --task APP-01 \
    --builder DEMO --rep 1 --iteration 0 --app-dir /path/to/exported-app

# 3. generate deterministic repair feedback for the failing checks
python3 runner/make_feedback.py --run-id APP-01-DEMO-r1-i000

# ...deliver feedback.txt to the builder, export the result, then re-run
#    run_oracles.py with --iteration 1 (whole-suite rule). Repeat ≤ 3.

# 4. build the processed dataset + metrics + trajectory
python3 runner/ledger.py && python3 analysis/metrics.py && python3 analysis/plots.py
```

Operator steps for the commercial builders (account access, prompt delivery,
export) are scripted in `benchmark/prompts/operator-runbook.md`.

## Pilot result snapshot (harness validation ONLY — not research data)

A real LLM (GLM via SDK, **not** Lovable/Bolt/Replit) generated APP-01; the suite
measured 19 pass / 16 fail; a repair attempt fixed 0/16 failures and introduced a
regression (session token moved into a cookie without HttpOnly/SameSite); the next
cycle repaired that regression. See
[pilot/PILOT_README.md](pilot/PILOT_README.md) for the corrected full trajectory
and the 15 harness defects the pilot+reviews caught and fixed before data
collection.
